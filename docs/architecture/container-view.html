How one order moves through ScaleForge

Build a trusted order from the cart

Checkout takes a fresh cart snapshot, checks its version, and asks the catalog for current prices. The server—not the browser—builds the order totals.

An idempotency key makes a retry safe: the same checkout request resumes or replays its order instead of creating a duplicate.

Reserve stock, then authorize payment

Orders creates a pending order and records the saga before asking inventory to reserve each item. Only after stock is reserved does payments authorize the amount.

If stock is unavailable or payment is declined, the order is cancelled and any reservation is released. Authorization places a hold; it does not capture funds yet.

Commit stock, capture, and confirm

After authorization, an event commits the inventory reservation. Once inventory confirms, payments captures the funds; only a successful capture moves the order to confirmed.

Each step is persisted and guarded against duplicate or late events. If a later step fails, the saga compensates where possible, and recovery continues without losing the order’s state.
